# フェーズ5 検証記録

## シミュレーション

`better-t-app` で `bun run simulate 1000 1 1` を実行した。引数は順に対局数、開始シード、全行動ログを出力する対象シード（省略可）。出力は JSON で、各攻撃の命中率・乱数・結果・ダメージ・残HPを記録する。未完了の対局はシードと全行動ログを出力する。初期配置でどちらかが地形上敵惑星に到達できない場合、双方が勝利不能な場合、2,000行動を超えた場合、または30勝以上のうち片方の勝率が10%未満・90%超の場合は異常として終了コードを1にする。

2026-10-31 の結果（シード1〜1000、同じCPU判断を双方に使用）:

| 指標 | 結果 |
| --- | ---: |
| 完了 / 未完了 | 1000 / 0 |
| human配置・先手の勝利 | 657（65.7%） |
| cpu配置・後手の勝利 | 343（34.3%） |
| 平均 / 最大ターン | 12.065 / 20 |
| 攻撃 miss / hit / critical | 14528 / 26253 / 4459 |

シード1のログでは、14ターン目にCPU戦艦の命中で先手惑星HPが12になり、その後のCPU戦闘機の攻撃は外れた。15ターン目に先手戦艦がCPU惑星へ4ダメージを与え、残HPが0となり勝敗が確定した。命中・外れ・残HPを確認した。

先手配置の勝率には偏りがある。CPU対CPUはプレイヤーの技能を反映せず、先手とマップ配置の影響も区別できないため、今回の結果だけで人間対CPUの初期HPや攻撃力を非対称に変更しない。現行値を暫定値とし、実プレイの勝率と感想を収集してから調整する。10%/90%のCI閾値は極端な退行を検出するための暫定値であり、65.7%を公平と保証するものではない。

到達不能の判定は他ユニットによる一時的な障害を無視し、地形と生存ユニットから敵惑星に攻撃可能な位置までの経路を調べる。双方が到達不能なら勝利不能と判定する。行動上限は停止性の検査であり、すべての配置で無限ループがないことの証明ではない。

## 自動検証

- 認証、作成、再取得、降参、勝利・敗北、履歴、古いバージョンの競合、保存失敗のロールバックをAPI結合テストで確認。
- 通信失敗・競合時の再取得と、攻撃時の演出側での再取得をユニットテストで確認。
- GitHub Actions は依存関係を固定インストールし、Biome lint、型検査、全 Bun テスト、100シードのシミュレーションを実行する。CIをマージの必須チェックにするには、リポジトリのブランチ保護設定で `Quality / quality` を必須にする必要がある。
- 既存ファイルに多数の整形差分があるため、CIはBiomeのlintを必須化し、全ファイルのフォーマット検査はまだ必須化していない。
