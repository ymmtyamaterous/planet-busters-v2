# Ver2 フェーズ0 検証記録

2026-10-31。フェーズ0の実装・ローカル自動検証は完了。実環境に依存するリリース前確認は下記に記載する。

## 互換性

- 既存の未コミット実装を維持し、対局にルール・マップの版を保存する。Drizzle 生成マイグレーションは旧行に `v1` を割り当てる。未対応版は拒否する。Ver1 の定義と実装は既存対局のため変更せず、新版を別に追加する。
- 空DBと初期マイグレーションのみの旧DBを実際に作成し、移行・再実行・旧対局の取得、行動、降参をテストした。実運用DB全体の監査や実際のバックアップ復旧は未実施。
- リリース前はサーバーを停止し、SQLite DB本体と、存在する場合はWAL等の関連ファイルを一貫した状態でバックアップする。復旧はサーバー停止中にバックアップ一式を別の場所に復元し、対象DBへの接続設定を変更して起動・対局確認する。使用環境固有のバックアップ方法と復元手順は本番導入前に検証する。

## シミュレーション

`better-t-app` で `bun run simulate:balance 100 1` を実行。各条件100局、シード1〜100、両陣営に同じCPU判断を使用。配置交換は地形を固定し、両惑星と艦隊の所有陣営を交換する。乱数は各対局で同じシードを使用するが、行動順が変わると同じ乱数が同じ攻撃に使われるとは限らない。

| 配置 | 先手 | 先手勝利 | 平均 / 最大ターン | 未完了 / 初期到達不能 |
| --- | --- | ---: | --- | --- |
| 元の配置 | human | 64/100 | 12.15 / 17 | 0 / 0 |
| 元の配置 | cpu | 48/100 | 13.00 / 20 | 0 / 0 |
| 所有者交換 | human | 48/100 | 12.48 / 20 | 0 / 0 |
| 所有者交換 | cpu | 64/100 | 12.51 / 17 | 0 / 0 |

ターン番号は既存仕様どおり human 手番開始時に増えるため、human先手とcpu先手では数え方が異なり直接比較できない。到達不能は地形のみを考慮する保守的判定。結果はCPU同士の限定的な基準値で、人間対CPUの公平性を意味しない。勝率目標やバランス変更は実プレイの感想とより多くの試行を踏まえて決める。

## 自動検証

- Bunテスト71件、型検査、ビルド、Biome lintは成功。Biome の既存警告と Phaser の大きなチャンク警告が残る。
- Playwright Chromium で登録、ログイン、狭い画面での新規対局・移動・ターン終了・再読み込み・再開・降参、別タブ競合、通信遮断と復帰を検証。通常ポップアップとポップアップ拒否時の攻撃演出、命中、勝利・CPU勝利と再読み込み、動きの軽減・演出スキップのキーボード操作も検証した（5件）。テスト専用のローカルサーバーは隔離インメモリDBのみを許可し、テスト用シナリオの配置・HPと対局乱数を固定する。本番サーバーにデータ準備用APIは含まれない。オフライン時の操作は保留され、オンライン復帰後に送信される。
- ビルド済みサーバーのSPAとアセット配信、不存在アセット・APIの404、空DBの起動時移行、登録・対局作成・再読込をブラウザで検証した（1件）。フロントエンドの `VITE_SERVER_URL` はビルド時に配信先へ設定する。
- 実行には `better-t-app` で `bunx playwright install --with-deps chromium` 後 `bun run test:e2e`、ビルド時に `VITE_SERVER_URL=http://127.0.0.1:3402` を指定して `bun run build`、続けて `bun run test:e2e:built`。CI に両E2E、ビルド、4条件の各25局のシミュレーションを追加した。ホストされたCI上での結果は未確認。
- 開発サーバーとの並行起動時にVite起動がタイムアウトしたため、テスト用キャッシュを分離し、テスト時は生成済みルートを使用する。修正後は連続実行に成功した。
